# SCIM User Provisioning Core — 0.4.0b4

## Purpose

Version 0.4.0b4 introduces a framework-neutral SCIM 2.0 User provisioning core.

The goal is to synchronize external lifecycle data into PyIAMKit without conflating provisioning with federation or authorization.

~~~text
SCIM client
   ↓
ProvisioningSource
   ↓
ScimProvisioningService
   ├── Identity profile
   ├── tenant Membership
   └── ProvisioningUser mapping
~~~

## Separate security identities

OIDC federation and SCIM provisioning are intentionally different.

~~~text
OIDC
provider_id + sub
→ authentication identity link

SCIM
source_id + externalId
→ provisioning resource mapping
~~~

An externalId is never interpreted as an OIDC subject.

## Tenant-scoped source

A ProvisioningSource binds:

~~~text
source_id
tenant_id
base_url?
~~~

The source manages one tenant Membership per provisioned User.

This avoids a dangerous global lifecycle assumption when the same Identity belongs to multiple tenants.

## ProvisioningUser aggregate

~~~text
ProvisioningUser
├── id                  # service-provider SCIM resource id
├── version             # ETag revision
├── source_id
├── identity_id
├── tenant_id
├── membership_id
├── user_name
├── external_id?
├── active
├── status
│   ├── ACTIVE
│   └── DELETED
├── created_at
├── updated_at
└── deleted_at?
~~~

The SCIM id is generated by PyIAMKit and is never reused.

## externalId

externalId is supplied by the provisioning client.

PyIAMKit scopes it to source_id.

~~~text
(source_id, external_id)
~~~

must be unique among active provisioning resources.

The same externalId may exist under another provisioning source.

## userName

userName is required.

Within one source it is unique case-insensitively among active resources.

The originally supplied casing is preserved for representation.

## Lifecycle semantics

### Create

~~~text
POST-like create
   ↓
create Identity
   ↓
activate Identity
   ↓
create tenant Membership(source=scim:<source>)
   ↓
activate Membership
   ↓
if SCIM active=false:
    suspend Membership
   ↓
create ProvisioningUser mapping
~~~

### active=false

~~~text
SCIM active=false
      ↓
Membership ACTIVE → SUSPENDED
      ↓
Identity remains ACTIVE
~~~

The global Identity is deliberately not disabled.

### active=true

~~~text
Membership SUSPENDED → ACTIVE
~~~

A REVOKED or EXPIRED Membership is not silently resurrected.

That requires an explicit new provisioning lifecycle.

### DELETE

~~~text
DELETE
  ↓
revoke managed Membership
  ↓
ProvisioningUser status=DELETED
  ↓
resource becomes unavailable through SCIM service
  ↓
Identity preserved
~~~

This is a tombstone, not hard deletion.

## ETag / If-Match

Each resource exposes:

~~~text
W/"<resource-id>-<version>"
~~~

Replace, PATCH and DELETE accept an optional If-Match value.

A non-matching value fails closed with ProvisioningPreconditionFailed.

The wildcard `*` is accepted as "resource exists".

## User attributes

Supported core User attributes:

- userName
- externalId
- displayName
- active
- name.givenName
- name.familyName
- emails

The primary email maps to the Identity User profile primary_email.

## PATCH subset

Supported paths:

~~~text
active
userName
displayName
externalId
name.givenName
name.familyName
emails
~~~

Operations are add, replace and remove where semantically valid.

userName and active cannot be removed.

Array-index SCIM paths and Group membership filters are not part of this milestone.

## Password handling

SCIM defines a password attribute, but this release intentionally does not accept or store password provisioning.

Credential material remains behind Authentication credential/secret boundaries.

## Group handling

SCIM Group resources are not implemented in 0.4.0b4.

No external group can therefore become a Role or Permission implicitly.

A later Group adapter must require explicit mapping/provisioning policy rather than treating group names as authorization truth.

## Persistence

SQLAlchemy adds:

~~~text
iam_provisioning_users
~~~

with foreign keys to:

- iam_identities
- iam_tenants
- iam_memberships

Active-resource partial unique indexes enforce:

~~~text
source_id + lower(user_name)
source_id + external_id
~~~

Deleted tombstones do not block legitimate reprovisioning.

## Transaction ownership

The SQLAlchemy provisioning repository follows the existing caller-owned transaction contract.

It never commits independently.

Cross-context provisioning should execute inside the host application's transaction boundary when durable atomicity is required.

## Events

The application service publishes minimal lifecycle events:

~~~text
ScimUserProvisioned
ScimUserReplaced
ScimUserPatched
ScimUserDeleted
~~~

Metadata contains resource/identity/tenant/source identifiers and version only.

## Security properties

- tenant-scoped lifecycle;
- no global Identity deletion from tenant SCIM;
- no federation/provisioning identifier conflation;
- no password storage;
- no Group → Role shortcut;
- no silent resurrection of revoked Membership;
- version preconditions supported;
- source-scoped externalId;
- non-reassigned SCIM id;
- deleted resource hidden while tombstone remains durable.

## Qualification

The release covers:

- create User;
- active/inactive Membership state;
- case-insensitive userName uniqueness;
- source-scoped externalId uniqueness;
- profile replace;
- ETag mismatch;
- PATCH supported attributes;
- unsupported Group PATCH rejection;
- delete/tombstone semantics;
- reprovision after delete;
- one-based pagination;
- SQLite repository conformance;
- live PostgreSQL persistence;
- Python 3.12/3.13;
- Ruff, mypy strict, coverage, wheel, examples and Bandit.
